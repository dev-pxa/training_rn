# 上线前检查清单

本文记录当前为了本地测试包、测试接口和自动化打包临时保留的配置。正式上线前需要逐项确认并修改，避免测试配置进入生产包。

## 1. 关闭 Android 明文 HTTP 访问

当前文件：

- `android/app/src/main/AndroidManifest.xml`

当前配置：

```xml
android:usesCleartextTraffic="true"
```

上线前建议改为：

```xml
android:usesCleartextTraffic="false"
```

原因：

- 当前测试接口使用 `http://49.232.34.105:8082`，release 包如果不允许明文 HTTP 会请求失败，所以测试阶段临时放开。
- 正式环境应使用 HTTPS，避免接口数据、登录信息和 token 在传输过程中暴露。
- 保持 `false` 更符合 Android 的生产安全策略。

## 2. 将默认接口环境切换为生产 HTTPS

当前文件：

- `src/services/environment.ts`

重点检查：

```ts
export const DEFAULT_ENVIRONMENT: ApiEnvironment = 'test';
```

以及：

```ts
production: {
  apiBaseUrl: 'https://api.qixuntong.com',
}
```

上线前建议：

- 确认生产域名真实可用，并且必须是 HTTPS。
- 将默认环境改为 `production`。
- 如果测试环境仍需保留，只允许在内部调试入口切换，不应作为正式包默认环境。

原因：

- 当前默认走测试环境，正式包首次安装后会请求测试接口。
- 用户登录、课程、考试、证书等业务数据必须进入生产环境。

## 3. 更换正式签名

当前文件：

- `android/app/build.gradle`

当前 release 仍使用 debug 签名：

```gradle
release {
    signingConfig signingConfigs.debug
}
```

上线前建议：

- 生成正式 keystore。
- 将 keystore 密码、alias、key password 放到本地安全配置或 GitHub Secrets。
- release 构建改用正式 `signingConfigs.release`。

原因：

- debug keystore 只适合测试安装。
- 正式发布后签名不可随意更换，否则用户无法平滑升级。
- 应用市场通常不接受 debug 签名包。

## 4. 确认 GitHub Actions 打正式包

当前文件：

- `.github/workflows/android-apk.yml`

当前已使用：

```yaml
./gradlew assembleRelease
```

上线前建议：

- 接入正式签名后，确认 Actions 使用正式签名构建。
- 如果发布到应用市场，优先考虑生成 AAB：

```bash
./gradlew bundleRelease
```

原因：

- APK 适合测试分发。
- AAB 更适合 Google Play 等应用市场分发。
- CI 产物必须和本地正式包签名、环境、版本一致。

## 5. 更新版本号和版本码

当前文件：

- `android/app/build.gradle`
- `package.json`

重点检查：

```gradle
versionCode 1
versionName "1.0"
```

以及：

```json
"version": "0.0.1"
```

上线前建议：

- 每次正式发布递增 `versionCode`。
- `versionName` 和 `package.json` 的 `version` 保持一致或建立明确规则。

原因：

- Android 安装升级依赖 `versionCode` 判断新旧版本。
- GitHub Actions 产物名会读取 `package.json` 的版本号，版本不一致会造成分发混乱。

## 6. 收敛内部调试入口

当前相关文件：

- `src/views/DeveloperDebugScreen/`
- `src/navigation/index.tsx`
- `src/views/ProfileScreen/index.tsx`

上线前建议：

- 确认生产包是否允许普通用户进入开发者调试页。
- 如果仅供内部使用，应通过构建开关、账号权限或隐藏入口限制访问。

原因：

- 调试页可以切换接口环境，正式用户误操作会导致请求测试环境或登录态失效。
- 内部调试信息不应暴露给普通用户。
